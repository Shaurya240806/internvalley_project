Secure Image Encryption:
Leveraging Python and Cryptographic Libraries

Encrypt images with AES-256-GCM, protect keys with RSA-OAEP, and share them with other users so that only the intended recipient can ever open them.

Main features

Authenticated accounts

Registration and login with salted, slow password hashing and rate-limited sign-in.

AES-256-GCM encryption

Every image gets a fresh random key and nonce. Tampering is detected by the authentication tag.

RSA hybrid encryption

The AES key is wrapped with the recipient's RSA public key using OAEP padding.

Secure transfer

Send encrypted images to another user and track Pending, Received and Downloaded status.

Dashboard and history

Statistics, recent activity and a complete encryption and transfer history.

DES learning module

An isolated, clearly-warned demo showing why DES is obsolete next to AES.

How it works

  1. UploadThe image is validated by its real content, not just its file extension.
  2. EncryptAES-256-GCM scrambles the image bytes with a one-time random key.
  3. Wrap the keyRSA-OAEP encrypts that AES key with the recipient's public key.
  4. TransferOnly ciphertext and the wrapped key are stored or sent.
  5. DecryptThe recipient's private key unwraps the AES key and the image is restored exactly.

Security features

  • Passwords hashed with scrypt (never stored in plain text)
  • CSRF protection on every form
  • HttpOnly, SameSite session cookies
  • Strict Content-Security-Policy and security headers
  • Private keys stored only in encrypted form
  • Per-user access control on every file and transfer
  • Authenticated encryption: modified files are rejected
  • Secrets read from environment variables, never from source code
